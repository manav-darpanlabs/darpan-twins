================================================================================
KEY COMPONENTS
================================================================================

1. DECISION PIPELINE
   Location: twins/tools.py (DecisionTool class)
   Process:
   - RAG Retrieval: Find 10 similar past decisions from 10K examples
   - Stage 1 (Decider): Generate natural text explanation (temp=0.3)
   - Stage 2 (Analyst): Extract structured JSON (temp=0.1)
   
   Output: {action, rationale, confidence (0-1), key_factors}
   Performance: 3-4 seconds per decision, $0.003 cost

2. RAG SYSTEM
   Location: twins/rag_retriever.py
   Data: 10,000 examples (13 MB JSON) + cached embeddings (117 MB)
   Similarity: Cosine similarity on 1536-dim vectors
   Method: text-embedding-3-small from OpenAI
   
3. PERSONALITY ENGINE
   Location: twins/twin_profile.py
   Model: OCEAN Big Five Traits
   - Openness (0-1): Adventurousness, creativity
   - Conscientiousness (0-1): Organization, carefulness
   - Extraversion (0-1): Sociability, outgoingness
   - Agreeableness (0-1): Compassion, cooperation
   - Neuroticism (0-1): Anxiety, sensitivity
   
   Derived: novelty_seeking, budget_sensitivity, distance_tolerance, rating_focus

4. WEB INTERFACE
   Location: app_streamlit.py (1,448 lines)
   Features:
   - Welcome onboarding
   - Location selection (8 preset Indian cities + custom search)
   - Restaurant card upload (vision-based extraction)
   - Real-time weather integration
   - Results dashboard (votes, factors, per-twin breakdown)
   
5. DATA SOURCES
   - RAG Examples: data/rag_examples.json (10K past decisions)
   - User Profiles: data/twin_profiles/ (1,000 JSON profiles)
   - Training Data: data/train_expanded.csv (300K rows)
   - Embeddings Cache: data/rag_embeddings.npy (117 MB)

DATA FLOW
================================================================================

USER INTERACTION:
1. User selects city (or searches custom)
2. Weather auto-fetches via Open-Meteo
3. User uploads two restaurant card images
4. System extracts card data via OpenAI Vision API
5. System loads 10 random twin profiles from 1,000 available

DECISION PROCESS (repeated per twin):
1. RAG retrieves 10 similar past decisions (cosine similarity)
2. Builds comprehensive prompt with:
   - User personality profile
   - OCEAN traits with explanations
   - Past behavior examples
   - Current restaurant options
   - Contextual information
3. Calls "The Decider" (Stage 1) - generates natural explanation
4. Calls "The Analyst" (Stage 2) - extracts JSON structure
5. Records decision in local memory store

AGGREGATION:
1. Counts votes (A vs B)
2. Extracts common decision factors
3. Computes breakdown by criteria
4. Calculates average confidence

RESULTS DISPLAY:
- Vote distribution chart
- Top factors (word cloud)
- Per-twin detailed table
- Expandable raw responses

================================================================================
NOTABLE ARCHITECTURE DECISIONS
================================================================================

1. NO TRADITIONAL ML MODELS
   Why: Avoids training/retraining infrastructure
   Method: Use LLM + prompt engineering + RAG for "soft learning"
   Benefit: Instant deployment, no model versioning

2. MULTI-STAGE PIPELINE
   Stage 1 (Decider): Natural personality-driven text (temp=0.3)
   Stage 2 (Analyst): Deterministic JSON extraction (temp=0.1)
   Benefit: Separates creativity from structure, robust error handling

3. RAG OVER FINE-TUNING
   Data: 10K diverse examples provide contextual learning
   Method: Semantic similarity search on embeddings
   Benefit: No gradient updates, easy to update with new examples

4. TEMPERATURE STRATEGY
   Decider: 0.3 (balanced - natural variation + consistency)
   Analyst: 0.1 (deterministic - reliable extraction)
   Result: 85-90% consistency while maintaining natural decisions

5. DUAL LLM PROVIDER SUPPORT
   Primary: OpenAI GPT-4o-mini
   Fallback: Anthropic Claude
   Benefit: Graceful degradation, vendor flexibility

AREAS FOR IMPROVEMENT
================================================================================

1. Embedding Cache Size: 117 MB could be optimized (quantization?)
2. RAG Coverage: 10K examples may miss rare edge cases
3. Prompt Fragility: Format changes require re-testing
4. No Active Learning: Doesn't learn from real user feedback
5. Limited Context Depth: Could track more historical patterns
6. API Dependencies: No offline capability
7. Single Provider: Anthropic fallback sometimes unreliable
8. Data Privacy: All profiles synthetic (no real user data)
